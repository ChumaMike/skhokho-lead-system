How should we architect the Activation System?

Three approaches — pick the one that feels right

A

New Tab in the Existing App ★ Recommended

Add a 3rd "Activate Leads" tab right next to Enter Lead and Discover Leads. Connects to Supabase to persist the activation queue + message history. Twilio sends the WhatsApp messages. Claude generates the message content per lead.

Pros

  • One app, one place for agents
  • Reuses all existing lead data, heat scores, product logic
  • Consistent UI — no context switching
  • Fastest to build on existing patterns

Cons

  • Adds Supabase dependency to a currently stateless app
B

Separate Activation App

Build a dedicated activation app as its own Next.js project. Shares the same Supabase and Twilio credentials. The lead system exports leads as JSON; the activation app imports them.

Pros

  • Clean separation of concerns
  • Can be deployed independently

Cons

  • Agents must switch between two apps
  • Lead data has to be exported/imported manually
  • Duplicates a lot of UI work
C

n8n Automation Backend

Use the existing n8n instance (already deployed on Railway) as the automation backbone. The lead app pushes leads to n8n via webhooks; n8n handles the message sequencing, Twilio calls, and tracking. App UI just shows the queue status.

Pros

  • Very powerful automation flows
  • n8n already deployed and running
  • Easy to modify sequences without code

Cons

  • Two systems to maintain
  • Less real-time UI feedback
  • n8n has its own complexity and failure modes
